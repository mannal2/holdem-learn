# 홀덤 판단 학습 앱

텍사스 홀덤을 처음 접하는 사람이 규칙을 읽고 끝내는 대신, 직접 답을 고르고 이유를 확인하면서 한 판의 흐름과 시작 패 판단 기준을 익히는 반응형 웹 앱입니다.

## 해결하려는 문제

입문자는 족보나 시작 패 차트를 외워도 실제 차례에서 무엇을 확인하고 왜 행동해야 하는지 연결하기 어렵습니다. 이 프로젝트는 설명 → 선택 → 즉시 피드백 → 요약의 짧은 학습 단위를 반복해 판단 과정 자체를 연습하게 합니다.

## Part 0과 Part 1에서 배우는 내용

- Part 0: 카드 구성, 족보, 프리플랍부터 쇼다운까지의 흐름, 기본 행동, 블라인드와 행동 순서, 모의 한 판
- Part 1: `AKs` 같은 시작 패 표기, 높은 카드·포켓 페어·수딧·커넥티드, 두 패 비교, 상대적 강도, 포지션, 같은 패의 포지션별 판단, 종합 도전

두 Part는 잠금 관계가 아닙니다. Part 0을 끝내지 않아도 Part 1에 직접 들어가 학습할 수 있습니다.

## 직접 판단하고 피드백받는 학습 방식

콘텐츠는 설명, 테이블 공개, 포지션 그림, 단일 선택, 복수 선택, 요약 Step으로 구성됩니다. 사용자가 답을 제출하면 정답 여부뿐 아니라 그 선택이 맞는 이유와 다른 선택이 맞지 않는 이유를 바로 보여줍니다. 각 Part의 종합 도전은 80% 이상이면 통과하며 횟수 제한 없이 다시 풀 수 있습니다.

## 기술 구조

- React 19, TypeScript, Vite
- React Router 기반 화면 이동
- React Context와 reducer 기반 진도 상태
- `ProgressRepository` 인터페이스와 `localStorage` 구현
- Vitest, Testing Library, Playwright
- 모바일 우선 CSS와 48rem 이상 데스크톱 레이아웃

`frontend/src/content`의 학습 데이터와 `frontend/src/features/learning`의 공통 학습 엔진을 분리했습니다. Lesson을 추가할 때 화면을 복제하지 않고 데이터만 추가할 수 있습니다.

## 진도 저장과 Spring Boot 확장 계획

현재 로그인 기능은 없으며 진도는 현재 기기와 브라우저의 `localStorage`에만 저장됩니다. 브라우저 데이터를 지우거나 시크릿 모드를 사용하면 진도가 사라지고 다른 기기와 동기화되지 않습니다.

화면은 저장 위치를 직접 알지 않고 `ProgressRepository`만 사용합니다. Spring Boot를 추가할 때 API 기반 Repository 구현으로 교체하면 학습 엔진, 화면, 콘텐츠 타입을 유지하면서 로그인 사용자별 서버 저장으로 확장할 수 있습니다.

## 실행 방법

Node.js와 npm이 설치된 환경에서 실행합니다.

```powershell
cd frontend
npm install
npm run dev
```

터미널에 표시된 로컬 주소를 브라우저에서 엽니다.

## 테스트 방법

```powershell
cd frontend
npm run lint
npm test
npm run build
npm run test:e2e
```

Playwright 브라우저가 없다면 최초 한 번 다음 명령을 실행합니다.

```powershell
npx playwright install chromium
```

2026-09-27 최종 검증 결과:

- `npm run lint`: 경고와 오류 없이 통과
- `npm test`: 20개 테스트 파일, 50개 테스트 통과
- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드 통과
- `npm run test:e2e`: 모바일 Chromium 3개, 데스크톱 Chromium 3개 시나리오 통과

## 주요 설계 결정과 장단점

- 콘텐츠와 렌더링 분리: Lesson 추가가 단순하지만 새로운 Step 종류를 만들면 타입과 렌더러를 함께 확장해야 합니다.
- Repository 경계: Spring Boot 교체 지점이 명확하지만 현재 단계에서는 인터페이스 파일이 하나 더 생깁니다.
- 확정 단계 저장: 답을 고르기만 한 상태가 아니라 정답 확인 또는 다음 이동 뒤를 저장해 복구 기준이 명확합니다.
- Part 독립 접근: 원하는 내용을 바로 배울 수 있지만 권장 학습 순서를 강제하지 않습니다.
- 모바일 우선 반응형: 작은 화면에서 안정적이고 데스크톱으로 자연스럽게 확장되지만 별도 네이티브 앱 기능은 제공하지 않습니다.

## AI를 활용한 개발 방식과 코드 이해 과정

요구사항, 학습 범위, 모바일 우선 방향, 로그인 전 진도 저장 방식과 구현 계획은 사용자가 검토하고 승인했습니다. AI는 승인된 계획에 따라 구현과 테스트 작성을 보조했습니다. 기능마다 실패 테스트를 먼저 확인하고 구현 후 전체 테스트를 실행했으며, 실제 브라우저 테스트에서 발견한 저장소 생명주기 문제도 수정했습니다.

프로젝트 소유자가 코드를 읽고 설명할 수 있도록 [코드 해설](docs/code-walkthrough.md)에 각 단계의 파일 역할, 데이터 흐름, 변경 위치와 설계 이유를 한글로 기록했습니다. AI가 코드를 작성했다는 사실을 숨기기보다, 요구사항 판단과 검증 과정 및 코드 이해 능력을 포트폴리오에서 함께 설명하는 것을 목표로 합니다.
