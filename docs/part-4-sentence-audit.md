# Part 4 문장·화면 연결 재검토

2026-10-06. 원문 검토 기준 코드: `701f32d`. 상태: 사용자 수정 승인 후 C01~C05·R01~R45 앱 반영 완료. 아래 현재 문구는 수정 전 원문이다.

## 범위와 확인 방법

`part4.ts`, `part4Questions.ts`의 7레슨·64화면·31문제를 레슨 순서대로 읽었다. 제목·본문·조건·보기·제출 후 해설·후보 상태·행동 기록과 공통 렌더러의 표시 문구를 함께 확인했다. 실행한 콘텐츠 모듈에서 실제 화면 번호와 문제 ID를 추출해 아래 위치와 대조했다. 이번 검토는 콘텐츠와 표시 코드 기준이며, 브라우저에서 64개 화면을 다시 조작한 검사는 아니다.

주요 문제는 비교 대상 생략, 앞 화면에 대한 불명확한 지시, 족보 강도와 보유 가능성 혼용, 질문과 보기의 호응 부족, 긴 조건문, 시간 순서 혼동이다. 아래 제안은 원문의 뜻을 설명하기 위해 길게 늘리기보다 판단할 대상과 행동을 명시한다.

번호 C는 여러 화면에 반복되는 문구, 번호 R은 특정 화면 문구다. '필수'는 의미나 연결을 오해할 여지가 있는 항목, '다듬기'는 이해는 가능하지만 표현을 더 자연스럽게 만들 수 있는 항목이다. 한 행에 함께 적은 질문·보기·해설은 같이 고쳐야 한다.

## 수정할 때 지킬 기준

- 이 문서의 수정안을 사용자가 승인했다. 정답 인덱스와 학습 기준은 유지하며 기존 문장 계획의 해당 부분을 보완한다.
- 문장의 '강하다'는 족보 비교, '유력하다'는 상대 보유 가능성으로 구분한다. 족보가 강하다는 이유로 보유 가능성 순위를 만들지 않는다.
- 가정은 문제를 풀기 위한 정보다. 잘못 줄여 없애거나 모든 상대에게 적용하는 일반 규칙으로 쓰지 않는다.
- 가능한 상대 패 예시는 독립된 후보다. 실제 상대 패나 전체 레인지, 동일 확률로 표현하지 않는다.
- 후보·공용 카드·칩 금액·정답 의미·7레슨·64화면·31문제·10/12 통과 기준은 유지하는 방향이다.
- 예/아니오 질문을 패 비교로 바꾸거나 질문·보기 의미가 바뀌는 항목은 저장 호환성을 검토한다. 필요한 경우 기존 `supersedes` 정책을 재사용한다. 단순한 표현 변경과 같은 방식으로 무조건 같은 ID를 유지하지 않는다.
- 순위가 불명확할 때는 정확한 확률이나 억지 1·2·3위를 추가하지 않는다. '어느 후보가 더 유력한지는 아직 모름'을 구체적인 카드·행동의 근거와 연결한다.
- 앱에 반영할 때는 문장 개별 치환 뒤 끝내지 않고 전체 흐름을 다시 읽는다. 특히 별도 카드 예시에서 원래 후보로 복귀하는 지점, 턴 드로우에서 리버 완성 실패로 넘어가는 지점, 질문과 보기의 문법·의미 호응을 확인한다.
- 후보 설명이 길어지면 조건 전체를 후보마다 반복하지 않는다. 모바일 실제 화면에서 줄바꿈·질문까지의 거리·보기 길이를 확인한다.

## 원문 검토 단계에서 하지 않은 일

앱 코드 수정, 채점 변경, 진도 삭제, 레슨 재배열을 하지 않았다. 문서의 현재 문구와 위치는 소스·실행된 콘텐츠 목록으로 대조했다. 문서만 추가하므로 앱 테스트·빌드를 다시 실행하지 않았다. 브라우저 64화면의 시각 검사는 후속 구현 검증에 필요하다.

- C01~C05·R01~R45를 반영했다. 원래 네 후보로 돌아오는 Q06 안내, 턴 드로우·리버 완성 실패를 구분하는 Q17, 체크 주체를 밝히는 Q26을 포함한다.
