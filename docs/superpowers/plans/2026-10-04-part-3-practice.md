# Part 3 추가연습 구현계획·진행 기록

> 실행: superpowers:executing-plans, 테스트: superpowers:test-driven-development, 완료: superpowers:verification-before-completion.

목표: 승인한 60문제로 여섯 레슨의 4문제 연습과 6문제 종합연습을 제공한다.
설계: `docs/part-3-practice-design.md`. 정적 콘텐츠와 기존 연습 엔진·LearningSession을 사용한다.

## 공통 제약과 판단

- 바탕화면 폴더에서만 작업한다. 사용자 지시에 따라 워크트리·커밋·push는 하지 않는다.
- 기존 수정과 저장 버전 1, Part 1·2 문제 ID·정답은 유지한다.
- 원문 승인 후 사용자가 구현을 명시적으로 요청했으므로 재승인 대기 없이 수행한다.
- 새 Page·DB·범용 문제 생성기는 만들지 않는다. 카드·확률 그림은 기존 디자인을 사용한다.
- 문제에 주어진 아웃츠 외의 답·강조·후보 목록은 제출 후에만 공개한다.

## 작업과 검증

1. 출제 계약 테스트 → 누락 레슨으로 실패 확인 → `part3Practice.ts`와 `practice.ts` 등록 → 4/6문제, 개념별 배분, 재출제·복원 검증.
2. 카드·정답·아웃츠 및 제출 전후 그림 테스트 → 필요한 공통 타입·렌더러만 확장 → 카드 소속·상대 예시·가정한 미래와 중복 후보 검사.
3. Part 3 브라우저 흐름 테스트 → 저장·복원·이전·오답 리뷰·새 시작·가로 넘침 확인 → 전체 단위 테스트·lint·빌드·브라우저 회귀 및 마지막 리뷰.

## 리뷰 초점

- 종합연습이 다른 Part 문제를 뽑지 않고 여섯 레슨을 모두 포함하는가.
- 턴·리버에서 공용카드 수와 카드 소속이 유지되는가.
- 제출 전 숫자 띠·상대 예시·계산식으로 답을 노출하지 않는가.
- 복수 선택과 제출 후 해설 그림이 새로고침·오답 리뷰에도 유지되는가.
- 기존 Part 1·2 저장을 함께 불러와도 기록이 유지되는가.

## 진행

- 시작: 공통 규칙·코드 구조 읽음. 출제 데이터 → 저장 검사에 공급되므로 같은 정적 문제 ID를 사용한다.
- 작업 1: 출제 계약 3개 실패 확인 후 등록. 출제·저장 관련 11개 통과. 같은 개념의 추가 한 문제를 Map으로 합쳐 회차 내 중복을 방지했다.
- 작업 2: 해설 그림·상대 예시·중복 후보 테스트 실패 후 구현. 후보 카드 문자열 오류를 유효한 숫자·무늬 검사로 재현하고 수정했다.
- 작업 3: 새 브라우저 검사 14개 통과. 초기 전체 단위 303개·브라우저 94개·lint·빌드 통과 후 최종 리뷰 수정분을 재검증 중이다.
- 최종 리뷰: 별도 읽기 전용 리뷰 완료. 페어+드로우의 스페이드 문구 오류와 다섯 장 혼합 강조를 재현 테스트 후 수정했다.
- 리뷰 판단: 중복 후보 두 목록, 양쪽 무승부 구성 카드 강조, 해설·복습에서 조건 유지는 승인 설계의 이해에 영향을 주므로 경미한 스타일 문제가 아니라 요구사항 누락으로 판단하고 수정했다. 회귀 테스트로 검증한다. 보류한 지적과 판단에서 제외한 항목은 없다.
- 작업 위치·커밋 판단: 사용자 확정 작업 위치와 요청 범위를 우선한다. 새 워크트리·커밋·push 없이 바탕화면 파일을 수정했으며 기존 수정은 보존한다.
- 최종 완료: 리뷰 수정분의 재현 테스트 RED→GREEN 확인. 전체 단위·화면 307/307, 브라우저 94/94, lint·빌드·diff 공백 검사 통과. 모바일 중복 후보 화면 직접 확인. 실제 기기·Safari·Firefox 미검증.
