# 커리큘럼 구현 공통 규칙

최종 갱신: 2026-10-06. 사용자가 승인한 학습·이동·저장 방식을 다음 커리큘럼에도 그대로 적용하기 위한 기준이다. 이전 계획이나 대화와 충돌하면 이 문서의 현재 규칙을 우선한다. 규칙을 바꾸려면 먼저 사용자에게 이유와 영향을 설명하고 승인받는다.

새 Part·레슨·추가 연습을 만들기 전에 이 문서와 [코드 해설](code-walkthrough.md)을 읽는다. 커리큘럼 구성과 카드 예시는 사용자와 먼저 확정한다. 포트폴리오 소유자가 코드를 읽을 수 있도록 중요한 로직은 한글로 설명하고, 데이터와 화면을 분리한다.

## 1. 공통 학습 엔진

- 콘텐츠는 `frontend/src/content`에 데이터로 작성한다. 레슨마다 React 화면을 복사하지 않는다.
- `LearningPage`와 `PracticePage`는 같은 `LearningSession`·`LearningStepRenderer`·카드·해설 화면을 사용한다.
- 설명, 테이블 공개, 단일 선택, 복수 선택, 포지션, 요약은 기존 `LearningStep` 타입을 재사용한다. 새로운 종류가 정말 필요한 경우에만 타입·렌더러·검증·테스트를 함께 확장한다.
- 저장·이동·스크롤처럼 모든 레슨이 지켜야 하는 동작은 공통 엔진에서 처리한다. 콘텐츠마다 같은 예외 처리를 붙이지 않는다.
- 모바일 우선 반응형 웹이다. 작은 화면에서도 카드와 선택지를 읽을 수 있어야 하고 데스크톱에서도 자연스럽게 보여야 한다.

## 2. 레슨과 추가 연습의 역할

- 레슨은 정해진 설명·카드 예시·고정 문제·해설·요약으로 이론을 가르친다. 레슨 재방문 때 문제를 무작위로 바꾸지 않는다.
- 레슨의 보기 순서도 고정하되, 여러 문제의 정답이 모두 첫 번째나 같은 위치가 되지 않도록 배분한다. 복수 선택도 정답이 항상 앞쪽에만 모이지 않게 한다. 두 시작 패 비교는 더 좋은 카드가 항상 패 A가 되지 않게 카드 배치·보기 이름을 함께 맞춘다. 순서 변경은 보기 ID·실제 카드·정답 의미를 유지해 기존 선택을 복원한다. 강도 질문은 ‘○○는 어떤 시작 패인가요?’로 쓴다.
- 추가 연습은 배운 이론을 새로운 카드에 적용하는 별도 문제 묶음이다. 레슨의 완료 여부나 점수에 영향을 주지 않는다.
- 종합 도전은 앞에서 이미 보여준 카드의 답을 암기하는 시험이 되지 않도록 새로운 카드 상황을 사용한다.
- 현재 Part 1은 38문제, Part 2는 48문제, Part 3은 60문제의 문제 풀을 사용한다. 일반 연습은 한 회차 4문제, 종합 연습은 6문제다. 종합은 고정된 별도 6문제가 아니라 해당 Part의 개념별 문제 풀에서 뽑는다. 다음 Part의 문제 수는 분량에 맞춰 별도로 승인받는다. ‘준비할 문제 수’와 ‘한 회차 출제 수’를 구분한다.
- Part 0에는 추가 연습을 두지 않는다. Part 1은 카드 특징·두 시작 패 비교·시작 패 강도·같은 패 다른 포지션에만 추가 연습을 연결하고, 마지막 시작 패 종합 도전에 종합 연습을 연결한다. 특징·비교·강도 각 9문제, 포지션 11문제이며 앞서 만든 종합 초안 6개도 각 개념의 문제 풀에 포함한다.
- Part 1 종합은 특징·비교·강도 각 1문제와 포지션 3문제(위치에 따라 판단이 달라지는 패·어느 위치에서도 강한 패·후반이어도 약한 패)를 뽑는다. 일반 포지션 연습은 각각 2·1·1문제다.
- 강도 판단은 ‘강함/괜찮음/상황에 따라/약함’ 네 등급의 모호한 경계를 묻지 않고, 해당 패에서 대비가 명확한 두 설명을 제시한다. 특징 문제는 복수 선택이고, 높은 카드 두 장의 기준은 J·Q·K·A로 문제에 명시한다. 포지션 문제는 인원·스택·앞선 행동·초반 UTG/후반 버튼을 명시하고 입문용 기준임을 알린다.
- 무작위 출제는 개념별로 균형 있게 하고, 후보가 충분하면 직전 회차 문제를 피한다. 문제·보기 순서는 회차를 시작할 때만 뽑아 저장한다. 화면 이동이나 새로고침마다 다시 뽑지 않는다.
- 현재는 React와 브라우저 저장으로 구현한다. 정적 퀴즈나 용어 설명만으로 DB·Spring Boot를 추가하지 않는다. 실제 서버 저장·인증 등 요구가 생기면 별도 설계한다.
- Part 3은 레슨 7개·고정 퀴즈 24문제를 먼저 구현한 뒤 별도 승인한 60문제 연습을 연결했다. 기본 레슨은 각 8·8·12·12·12·8문제, 마지막은 여섯 레슨에서 한 문제씩 뽑는 종합연습이다. 상세 기준은 part-3-practice-design.md를 따른다.

## 3. 저장과 복원: 마지막으로 보던 학습 단계

레슨과 추가 연습은 동일한 원칙을 적용한다.

| 사용자 행동 | 저장·복원 기준 |
|---|---|
| 답을 고름 | 현재 단계와 실제 선택 ID를 저장 |
| 정답 확인 | 현재 단계 그대로 저장. 선택·제출 여부·해설·점수 보존 |
| 다음 | 다음 단계로 저장 위치 변경 |
| 이전 | 이전 단계로 변경. 당시 선택과 제출한 해설 복원 |
| 홈·목록으로 이탈하거나 새로고침 | 마지막 저장 단계로 복귀. 제출했다면 체크와 해설 함께 복원 |
| 이미 제출한 문제를 다시 봄 | 다시 채점하거나 점수를 중복 집계하지 않음 |
| 다시 풀기·처음부터 복습 | 명시적으로 새 레슨 시도 시작 |

‘마지막 화면’은 학습 단계와 답·해설을 뜻하며 정확한 픽셀 스크롤 위치를 뜻하지 않는다. 복귀·이전·다음 시 문제 시작 부분이 바로 보여야 한다. 답 선택이나 정답 확인만 할 때에는 강제로 위로 스크롤하지 않는다.

`LearningSession`은 항상 제출한 현재 단계를 저장한다. 레슨과 연습을 나누는 `persistCurrentOnSubmit` 옵션은 제거했으며 다시 도입하지 않는다.

레슨 진도는 `holdem-learning-progress`, 연습은 `holdem-practice-progress`에 저장한다. 로그인 없이 현재 기기·브라우저에만 남는다. 기존 데이터는 함부로 지우지 않는다. ID·보기 의미·정답·Step 순서를 바꿀 때는 저장 호환성 및 마이그레이션을 검토한다. 이번 복귀 정책 변경은 기존 저장을 초기화하지 않으며 이전 정책으로 이미 저장된 위치는 그대로 읽는다.

## 4. 목록과 완료 상태

### 홈의 Part 카드

- 학습 기록이 없으면 ‘미시작’.
- 해당 Part에 이어할 위치 또는 끝까지 푼 레슨 기록이 있으면 ‘학습 중’. 완료 레슨이 0개여도 이어할 위치가 있으면 미시작이 아니다.
- 저장된 Part 통과 기록이 있으면 ‘완료’.
- `n/전체 레슨 수`는 기존의 끝까지 푼 레슨 수다. 종합 도전의 통과 여부와 같은 뜻으로 사용하지 않는다.
- 홈 상단 이어하기는 현재 레슨으로 직접 이동하고, Part 카드 링크는 그 Part의 목록으로 이동한다.

### 각 레슨 행

| 우선순위 | 상태 | 버튼 |
|---|---|---|
| 1. 저장된 진행 위치가 있음 | 학습 중 | 이어하기 |
| 2. 통과 기준이 있는 도전의 최신 결과가 미통과 | 재도전 필요 | 다시 풀기 |
| 3. 끝까지 완료한 일반 레슨 또는 통과한 도전 | 완료 | 복습하기 |
| 4. 기록이 없음 | 미시작 | 시작하기 |

‘이어하기’에는 `?restart=1`을 붙이지 않는다. 재도전·복습 등 명시적인 새 시도에만 붙인다. 재시작 표시는 새 시도의 첫 단계·빈 답을 저장한 뒤 주소에서 제거한다. 계속 남겨 두어 새로고침 때마다 다시 시작하게 만들지 않는다. 이미 완료했던 레슨을 복습하다 나가도 진행 위치가 있으면 이어하기를 우선한다.

실패 여부는 특정 레슨 ID가 아니라 `passingPercentage`와 최신 결과로 판단한다. 현재 종합 도전의 통과 기준은 80%다. 최고 점수와 최신 시도 점수를 혼동하지 않는다. 과거 Part 통과 기록은 기존 방식대로 유지하지만 최신 도전이 실패했다면 해당 행은 재도전 필요다.

### Part 목록 상단 버튼

1. 진행 중 레슨이 있으면 그 위치로 이어하기.
2. 진행 중 위치가 없고 미통과 도전이 있으면 종합 도전 다시 풀기.
3. 그 외에는 순서상 첫 미완료 레슨. 일부 레슨을 마쳤으면 다음 레슨 시작하기.
4. 모두 완료했으면 처음부터 복습하기.

다른 Part의 기록이나 추가 연습 점수로 레슨 이어하기 대상을 바꾸지 않는다.

## 5. 화면 이동과 불필요한 기능

- 레슨·레슨 결과·Part 결과의 왼쪽 상단에 해당 Part 목록으로 가는 ‘레슨 목록’ 링크를 둔다. 결과에서 빠뜨리지 않는다.
- 추가 연습의 상단 돌아가기도 해당 Part 목록으로 이동한다. 레슨 첫 화면으로 이동하지 않는다.
- 같은 목적의 목록 복귀 버튼을 하단에 중복해서 추가하지 않는다.
- ‘연습 잠시 나가기’는 두지 않는다. 저장은 자동이며 상단 돌아가기로 이탈한다.
- 레슨 결과의 다시 풀기·새 카드로 연습하기·다음 레슨은 각각 복습·응용·진행으로 역할이 다르므로 유지한다.
- 추가 연습 링크는 관련 레슨 제목 옆에 색이 다른 링크로 배치한다. 종합 도전 옆은 종합 연습으로 표시한다. 하단에 별도 연습 목록을 중복 배치하지 않는다.
- ‘학습 경로’, ‘최근 완료 결과 보기’ 기능을 다시 추가하지 않는다. 새 화면의 목록 명칭은 ‘레슨 목록’을 사용한다.

## 6. 추가 연습 시작·결과 화면

- 새로 들어왔을 때 별도 ‘한 번에 N문제…’ 안내 박스를 만들지 않는다. 상단 소개 영역에 연습 시작 버튼을 넣는다.
- 진행 중 회차가 있으면 같은 상단 영역에 이어서 연습하기와 새 문제로 연습하기 버튼을 넣는다.
- 진행 중 회차를 새 문제로 교체하려면 기존 답이 교체됨을 확인받는다. 취소하면 현재 회차를 그대로 유지한다.
- 문제 풀이 중에는 시작·교체 버튼을 중복 표시하지 않는다.
- 완료 직후에는 점수와 틀린 문제의 카드·내 선택·정답·해설을 보여주고 새 문제로 연습하기를 제공한다. 결과 박스는 삭제 대상이 아니다.
- 완료 상태로 목록에 나왔다가 다시 들어가거나 새로고침하면 결과 대신 새로운 연습 시작 화면을 보여준다. 완료 기록은 남겨 두되 결과 화면 표시 여부(`showResult`)는 저장하지 않는다.
- 안내·저장 오류·교체 확인처럼 실제 행동에 필요한 정보는 유지한다. 시작 안내 박스를 없앴다는 이유로 오류 안내까지 없애지 않는다.

## 7. 홀덤 콘텐츠 작성 기준

- 한국어 명칭은 '드로우'로 통일한다. 플러시 드로우·스트레이트 드로우·오픈엔디드 드로우·거샷 드로우로 쓴다.
- Part 3 아웃츠는 문제에서 지정한 족보를 완성하는 미확인 카드 수로 묻고 추가 공개 정보의 범위를 명시한다. 드로우 완성 확률과 실제 승률을 혼동하지 않는다. 2·4 법칙은 근삿값이며 한 장/두 장을 보는 조건을 명시한다.
- 카드 상황은 공용 카드 3/4/5장을 지원한다. 선택 문제의 `table.stage`는 생략하면 기존처럼 flop이다. 턴·리버 문제는 공개 단계와 실제 카드 수를 맞춘다.
- 공용 카드와 내 카드를 함께 표시할 때는 공통 `PokerTable`을 사용한다. 위쪽 초록색 영역에 ‘공용 카드’, 아래쪽 별도 배경·테두리 영역에 ‘내 카드’ 2장을 표시한다. 레슨·추가연습·오답 리뷰 모두 같은 구분을 유지하며 같은 테이블 배경에 두 그룹을 섞지 않는다.
- 앞선 보드에서 족보가 완성되는 설명은 기존 배치를 유지하는 `table-reveal`과 `highlightedCards`를 사용한다. 완성에 사용한 5장만 금색 테두리로 강조하고, 사용하지 않은 카드도 남긴다. 새 턴 카드는 보드에 추가됐음을 문구로 명시한다. 독립 족보 예시는 `handExamples`, 아직 나오지 않은 아웃츠 목록은 `ExplanationStep.cardGroups`를 사용한다.
- 상대 족보 비교에서는 같은 보드를 유지하고 `opponentCards`로 ‘가정한 상대 카드’를 별도 표시한다. 실제 공개 패로 단정하지 않으며 어떤 공용 카드와 각 개인 카드가 족보를 만드는지 설명한다. 비교의 카드 중복도 검증한다.
- 족보를 설명할 때 이름만 나열하지 않고 실제 5장 카드 예시와 구성 이유를 함께 보여준다.
- 현재 완성된 족보와 보드의 위험은 구분한다. ‘내가 A 원 페어다’와 ‘상대가 플러시일 수 있다’는 동시에 참일 수 있다.
- 공개된 카드만으로 상대의 실제 패나 승패를 확정하지 않는다.
- 입문 설명은 용어·기호만 나열하지 않고 뜻과 카드 예시 또는 판단 이유를 함께 쓴다. ‘보드·키커·스택·100BB·오픈 레이즈’ 같은 표현은 해당 개념을 설명하는 레슨에서 풀어 쓰며, 독립 연습에 필요한 조건은 그 화면에도 제공한다.

- 이미 명확한 문구를 길게 반복하지 않는다. 필요한 정의·이유를 짧은 문장과 목록으로 나누고, 카드·문제·선택지를 읽는 데 방해되지 않는지 모바일에서 확인한다.
- 2026-10-03 사용자 승인: 입문 규칙은 핵심 한두 문장과 카드·칩·자리 도식으로 설명한다. 장문으로 모든 예외를 나열하지 않는다. Part 0의 개인 카드·공용 카드 3+1+1·최종 다섯 장·행동·6인 자리 순서에 적용했다. 이미 명확한 족보 카드 예시와 단계별 테이블은 유지한다. 다른 Part를 일괄 변경하지 않는다.
