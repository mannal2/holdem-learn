# Part 4 교육 보완 — 승인된 구현 계획

> 과거 구현 기록이다. 현재 기준은 2026-10-06 전체 승인한 [연속 추론 커리큘럼](part-4-sequential-curriculum-design.md)이다.

2026-10-05 사용자 승인. 기준 커밋: fc61a04. 실제 작업 위치는 바탕화면 holdem이다.

## 목표·범위

7레슨·56화면·24문제와 순서를 유지한다. 패 종류 → 카드 후보 → 단서 → 갱신의 흐름을 강화한다. 설명은 한두 문장과 기존 카드·자리·칩 도식으로 제공한다. Part 0~3·추가연습·서버는 변경하지 않는다.

## 승인한 레슨별 작업

- 레슨 1: 보드를 K♠ 8♠ 3♣로 통일. 셋·원 페어·페어 없음·플러시 드로우 예시를 거쳐 레인지 정의로 연결한다. 강도는 이 보드의 예시 사이 비교이며 드로우는 별도 가능성이다.
- 레슨 2: 자리 그림에 시작패 예시를 연결한다. 7페이지는 이전 첫 레이즈·재레이즈에서 확인한 패를 근거로 이번 재레이즈에서 주의할 패 종류를 판단한다.
- 레슨 3: 제목과 상태 표시를 현재 강도/미래 가능성으로 명확하게 하고 기존 족보·드로우 문제는 유지한다.
- 레슨 4: 베팅의 주체를 명확하게 하고 5·7페이지는 드로우 콜·셋 체크의 이유를 묻는다.
- 레슨 5: 큰 베팅 뒤 확인한 패가 대부분 강했다는 관찰로 조건을 수정한다. 7페이지는 강한 패/블러프의 가능성을 어떻게 비교할지 묻는다.
- 레슨 6: A K♥ Q♥ / B J♠ 10♠ / C 8♣ 8♦를 끝까지 고정. 충돌 패는 별도 확인용 후보. 턴 큰 베팅과 해당 상황의 관찰을 연결해 A를 더 주의하지만 B·C도 가능함을 설명한다.
- 종합: 새 카드 사례의 6문제 유지. 콜 이유·관찰 근거·턴 판단을 보완하고 5/6 통과를 유지한다.

## 저장 호환성

후속 승인: 레슨 2의 5페이지는 ‘앞사람이 레이즈한 금액을 다시 올리는 행동을 무엇이라고 하나요?’와 재레이즈/콜 보기, 단일 행동 그림을 사용한다. 7페이지는 불필요한 첫 레이즈 기록을 제거하고 ‘이전에 본 모습’에서 재레이즈 뒤 공개한 패가 대부분 AA·KK·AK였음을 설명한 뒤 ‘이번 상황’과 질문으로 연결한다. Q04·Q05-v2의 보기 ID·정답 의미·페이지 위치는 유지해 기존 선택·점수는 그대로 복원한다.

검증: 새 질문의 브라우저 테스트 실패 확인 후 수정. 전체 단위 352개, Part 4 모바일/데스크톱 브라우저 26개, lint·빌드 통과. 두 문제의 선택·해설·점수는 새로고침 후 유지하며 가로 넘침 없음. 테스트에서 CSS로 표시되는 화살표를 본문 문자열로 검사한 오류는 실제 행동 항목의 순서를 검사하도록 고쳤다. 별도 사용자 제목 변경은 이번 커밋에서 제외한다.

후속 승인: 레슨 6의 2페이지는 A·B·C·D를 모두 보여준다. A K♥ Q♥ / B J♠ 10♠ / C 8♣ 8♦를 후속 화면까지 유지하고, 내 A♥와 겹치는 D A♥ Q♣만 제외한다. ‘확인용 후보’ 표기를 제거했다. Q15의 기존 세 보기 ID와 카드의 대응·정답 ID는 그대로 유지하고 B에만 새 보기 ID를 추가한다. 따라서 구판 선택·점수도 그대로 복원된다.

후속 검증: 후보 소속·다음 화면 연결 테스트의 실패 확인 후 수정. 전체 단위 352개, Part 4 모바일/데스크톱 브라우저 24개, lint·빌드 통과. 구판 정답 ID의 선택·해설을 새로고침과 이전 이동 후에도 보존하며 가로 넘침 없음. 별도 사용자 변경인 레슨 4 체크 설명 제목은 유지하고 이 작업 커밋에는 포함하지 않는다.

의미가 바뀐 Q05·10·11·14·18·22·23·24에는 새 문제·보기 ID를 부여한다. 문구·그림만 보완한 문제는 기존 ID를 유지한다. 수정된 문제의 구판 선택·제출만 정리하고 현재 화면·다른 답·다른 Part·완료·최고 기록을 보존한다. 구판 오답에는 새 해설을 붙이지 않고 안내를 제공한다.

## 실행과 검증

1. 호환성·화면 표현·채점 테스트 작성 → 실패를 확인한다.
2. 콘텐츠·그림·저장 호환성 구현 → 대상 테스트를 통과시킨다.
3. 전체 테스트·lint·빌드·모바일/데스크톱 브라우저 검증 → 기록한다.
4. 독립 코드 검토·문서 갱신 → 검증 완료 후 작업 전체를 한 번 커밋한다. 푸시하지 않는다.

## 작업 기록

- 사전 점검: 원래 선택 저장은 화면 번호 기반, 제출·오답은 문제 ID 기반이다. 둘을 함께 처리해야 한다.
- 결정: 새 자리 컴포넌트 대신 기존 설명의 cardGroups를 사용한다. 턴 금액은 후보 그림에서 기존 베팅 비교 도식을 재사용한다.
- 결정: 현재 복귀 화면은 유지한다. 변경된 앞 문제를 아직 풀지 않았다면 마지막 화면에서 ‘남은 문제 풀기’로 안내한다. 누락된 문제를 건너뛰고 5/5 등으로 종합을 통과하지 않게 한다.
- 사용자 확정 작업 위치·작업당 한 번 커밋 규칙을 우선하므로 새 워크트리·단계별 커밋은 만들지 않는다. 대화에서 승인된 계획을 이 문서로 기록하고 직접 구현한다.

## 완료 검증

- 구판 제출·미제출 선택 복원, 미제출 문제 완료 방지, 구판 오답 안내, 턴 금액 그림의 실패 테스트를 확인한 뒤 구현했다.
- 전체 단위·컴포넌트 351개 통과. 전체 Chromium 모바일·데스크톱 흐름 116개 통과. 독립 검토의 금액 누락 보완 뒤 Part 4 브라우저 22개를 다시 통과했다.
- 모바일 390×844와 데스크톱 1440×900에서 전체 Part 4 56화면, 새로고침·홈/목록 이탈 복원, 다른 Part 유지, 구판 종합에서 변경된 문제 재응답, 4/6 실패·5/6 통과를 검사했다. 레인지·자리/시작패·턴/해설 스크린샷도 확인했다.
- 독립 읽기 전용 검토: 중요한 문제 1건(제출 후 턴 팟·베팅액 그림 누락)을 수정하고 해설·오답 결과 회귀 테스트를 추가했다. 그 외 중요/치명적 지적 없음.
- lint·프로덕션 빌드 통과. 빌드의 단일 묶음 500kB 초과 경고는 남아 있으며 이번 교육 수정 범위에서 코드 분할은 하지 않는다.
- 커리큘럼 공통 규칙·코드 해설·기존 Part 4 설계에 최신 변경과 저장 정책을 기록했다. 작업 한 번 커밋, 푸시하지 않는다.
