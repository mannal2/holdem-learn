# Part 4 연속 추론 구현 기록

기준: [승인 커리큘럼](part-4-sequential-curriculum-design.md), 2026-10-06 사용자 구현 승인. 시작 커밋 59d4d7d.

## 실행 순서

1. 64화면·31문제, 대표 핸드/세 변형/종합 세 핸드 콘텐츠 → 독립 정답·후보 연속성·제출 전후 렌더링 검사.
2. 구판 Part 4 기록만 삭제, 구판 URL 안내 → 다른 Part 보존·새 기록 재삭제 방지·쓰기 실패 검사.
3. 단위·lint·빌드·브라우저 전체 흐름 → 최종 독립 검토, 문서 갱신, 한 번 커밋.

## 사전 결정

- 사용자 지정 바탕화면 폴더에서 직접 작업한다. 새 워크트리와 중간 커밋을 만들지 않는다.
- 기존 part4.ts의 사용자 변경은 체크 제목 한 줄이다. 새 구성에서도 체크만으로 강한 패를 제외하지 않는 설명을 보존한다. 전체 콘텐츠 교체와 직접 겹치는 변경이다.
- 공통 학습 엔진과 도식을 재사용하고, 후보 변화는 기존 상태 문구에 별도 줄로 적는다. 계산기·새 문제 UI를 만들지 않는다.
- 구판 레슨 ID와 개정판 ID를 분리한다. 구판을 카탈로그 검증 전에 정리해야 다른 Part까지 손상된 기록으로 초기화되는 일을 막을 수 있다.

## 검증 기록

- 구판 콘텐츠에서 신규 요구 테스트 42개가 실패하는 것을 확인한 뒤 구현하여 통과시켰다. 구판 URL·Q30 조건/도식 검사도 실패 재현 후 수정했다.
- 최종 전체 단위·컴포넌트 테스트: 38파일, 358개 통과.
- lint 통과. TypeScript 검사와 Vite 프로덕션 빌드 통과. JS 번들 526.36kB로 기존 500kB 경고는 남아 있다. 코드 분할은 이번 커리큘럼 범위에 포함하지 않았다.
- Part 4 브라우저 검사 20개에서 전체 화면·저장 복원·구판 정리·통과 경계를 통과했다. 첫 실행은 Windows 종료 단계에서 멈췄으므로 검사 완료와 실행기 종료를 구분했다. 해당 실행기만 종료하고 전체 브라우저 검사를 별도로 실행했다.
- 최종 전체 브라우저 검사: 모바일·데스크톱 Chromium 114개 통과, 실행기 정상 종료(3.7분). 문서 상대 링크 및 `git diff --check` 통과.
- 모바일 Q11·Q30, 데스크톱 Q14 캡처를 직접 확인했다. 실제 휴대전화 및 Safari/Firefox는 검증하지 않았다.

## 최종 검토와 결정

- 독립 검토에서 Q20·Q24 프리플랍 조건이 미래의 행동 흐름을 미리 알려주는 문제를 발견했다. 회귀 테스트 2개가 실패함을 확인하고 안내를 단계 이름으로 교체했다. 최종 358개 테스트에 포함되어 통과했다.
- 카드 사실·드로우·행동/팟·후보 연속성·조건부 정답·기록 정리에서 추가 수정 사항은 없었다. 실제 UI와 실행 결과는 검토자 대신 구현자가 별도 확인했다. 실제 상대 빈도나 GTO 최적성은 검증 대상이 아니다.
- Q30 및 변형 C는 레이즈 총액을 초기 팟에 대한 단순 베팅 비율로 표시하지 않는다. 기존 행동 이력과 문제 조건에 초기 팟·베팅·레이즈 총액을 명시한다. 새 레이즈 전용 도식을 만들지 않는 최소 변경이다.
- 기존 사용자 수정 제목 ‘체크했다는 이유만으로 강한 패를 지우지 않아요’를 레슨 6의 네 번째 화면에 보존했다.
- `LearningSession`을 재사용하고 상태 문구의 줄바꿈만 추가했다. 문제 전용 화면이나 추론 계산기를 추가하지 않았다.
- 구판 기록은 현재 카탈로그 검사 전에 정리한다. 전환 저장 실패 시 원본을 삭제하지 않으며 경고를 표시한다. 새 ID에는 삭제가 다시 적용되지 않는다.


## 후속 작업: 제목 통일과 실제 디자인 비교 (2026-10-06)

사용자 승인한 레슨 제목 7개만 수정하고 설계 문서의 제목을 맞췄다. 디자인은 이번 요청대로 차이를 조사했다. CSS 변경은 없다.

실제 브라우저에서 Part 1·2·4 목록, Part 1 시작 패 카드, Part 3 플랍 공개, Part 4 플랍 후보를 비교했다. 모바일 390×844에서도 후보 영역을 확인했다.

| 항목 | 확인 결과 |
|---|---|
| 목록 | 바깥 세로 여백 80px, 레슨 행 여백 16px·모서리 12px로 동일. Part 1~3의 추가 연습 링크 때문에 일부 행의 높이가 달라짐. |
| 레슨 틀 | 데스크톱 폭 768px, 상단 여백 32px·모서리 16px로 동일. |
| 공용 카드 테이블 | Part 3·4의 배경·테두리·여백 24px·모서리 16px가 동일. Part 4는 설명 대신 공개 단계를 표시해 테이블 높이가 조금 낮음. |
| 실제 카드 | Part 3 테이블과 Part 4는 폭 약 73.6px·글자 17.6px로 동일. Part 1의 두 장 예시는 최대 72px·글자 21.6px. 공통 카드 색·그림자·모서리는 같음. |
| 후보 상자 | Part 4만 점선 테두리, 여백 12px/5.6px·모서리 12.8px. Part 1 패 상자는 실선·여백 16px·모서리 16px여서 Part 4가 조밀하게 보임. |
| 구역 간격 | Part 4 후보 흐름은 12px, Part 3 테이블 구역 간격은 16px. Part 4에는 별도 행동 이력도 있어 화면 정보가 더 조밀함. |

가장 먼저 맞출 후보는 후보 상자의 실선 테두리·모서리·구역 간격이다. 다만 네 후보를 모바일 두 열에 표시하므로 모든 안쪽 여백을 Part 1과 똑같이 늘리면 카드 공간이 줄어든다. 이 차이는 반응형 배치와 함께 조정하는 것이 좋다.

검증: Part 4 콘텐츠 테스트 41개와 TypeScript/Vite 빌드 통과. 실제 목록·레슨에서 수정 제목 표시 확인. 기존 번들 크기 경고 유지. 제목만 바꿨으므로 ID·순서·기록 전환은 추가하지 않았다.

## 후속 작업: 후보 영역 스타일 통일 (2026-10-06)

사용자 승인으로 후보 상자를 공통 패 상자와 같은 실선 색·16px 모서리로 변경했다. 공용 카드·행동 이력·후보 사이 간격은 12px에서 16px로, 후보 상자 사이 간격은 9.6px에서 공통 패 그룹과 같은 12px로 맞췄다. 모바일 두 열의 카드 공간을 위해 후보 상자 안쪽 여백은 유지했다.

검증: 실제 데스크톱·390×844 모바일에서 실선·16px 모서리·구역 간격과 가로 넘침 없음을 확인했다. 기존 Part 4 브라우저 검사 20개 통과(전체 64화면의 모바일·데스크톱, 제출 전후 표시·복원 포함). TypeScript/Vite 빌드와 diff 공백 검사 통과. 기존 번들 크기 경고 유지.

## 후속 작업: 첫 화면의 불필요한 용어 제거 (2026-10-06)

사용자 요청으로 공통 상황 안내의 ‘앤티·레이크 없음’을 삭제하고 첫 자리 도식의 ‘대표 핸드 H · 상대는 버튼’을 ‘이번 판에서 상대는 딜러 버튼 자리예요’로 변경했다. 다른 Part 4 화면·문제의 대표 핸드 표기도 ‘이번 판’ 또는 ‘앞서 본 판’으로 맞췄다. 내부 사례 변수·카드·조건의 수치·정답·문제 ID는 유지했다.

검증: Part 4 콘텐츠 테스트 41개·TypeScript/Vite 빌드·diff 공백 검사 통과. Part 4 콘텐츠에서 앤티·레이크·대표 핸드 H 표현이 남지 않음을 검색으로 확인했다.

## 후속 작업: 전체 문구를 짧고 쉬운 표현으로 수정 (2026-10-06)

[개정 문장 계획](part-4-language-revision-plan.md)을 사용자 승인 후 구현했다. 공통 가정, 설명·목표·요약, 31문제의 질문·보기·해설, 후보 상태를 함께 정리했다. 어려운 ‘무게·개선·내부 순위·공격 약화’를 실제 패와 행동으로 바꾸고 H 잔여 표기를 삭제했다. 백도어 클럽은 턴·리버 모두 클로버가 필요하다는 설명으로 바꿨다. 블라인드 2칩에 더하는 콜 금액은 ‘4칩 추가 콜’로 표시했다.

공통 엔진·화면·CSS·저장 로직은 변경하지 않았다. 레슨 3의 이유는 기존 설명 본문에 짧은 세 문장으로 넣었다. 모바일 캡처 확인 후 후보 아래 이유를 한 번 더 줄였다. 카드에는 핵심만 적고 문제 조건에는 전체 가정을 유지해 원래 조건을 축소하지 않았다.

검증: 전체 38파일·358개 단위/컴포넌트 테스트, Part 4 모바일·데스크톱 브라우저 20개(64화면·저장 복원·종합 경계), lint·TypeScript/Vite 빌드 통과. 기존 번들 크기 경고 유지. 실행한 콘텐츠를 이전 커밋과 비교해 문구를 제외한 카드·ID·화면 순서·정답·도식 구조·금액·강조가 같음을 확인했다. 행동 이력은 승인한 콜 총액/추가액 표현만 바뀌었다. 모바일 Q11/Q14와 데스크톱 Q30의 실제 캡처도 확인했다.

첫 전체 검사에서 이전 문구를 찾는 단위 단정 4개와 브라우저 단정 2개가 실패했다. 새 조건 표시와 이미 승인된 레슨 제목으로 단정만 수정하고 전체 검사를 다시 통과시켰다. 독립 정답·후보 연속성·제출 전 비공개·9/12 및 10/12 경계 검사는 유지했다.
